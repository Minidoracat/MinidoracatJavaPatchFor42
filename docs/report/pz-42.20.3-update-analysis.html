1. 官方 42.20.3 動了什麼（changelog × bytecode 實證）

全 jar 23,735 → 23,740 class：新增 6、移除 1、變更 143。

A. MP 玩家上限 254＋滿員時管理員可進

  • GameServer：新增 delayed-disconnect 機制（MainLoopDelayedDisconnectQ 家族）、getFreeSlot 收 private、receiveClientConnect 重構；UdpConnection／UdpEngine／QueuePacket 配合。
  • LoginPacket.processServer：client 版本不符時提前 return（舊版 log＋踢人後竟繼續跑完登入流程＝bug）。

B. 修 client 卡「Loading Map」forever —— 與我方 W4-1 同戰場

  • PlayerDownloadServer（+6,335 bytes，9→16 方法）新增 pending 機制：新內部類 QueuedRequest／PendingChunk／OutOfRangeRequest＋新封包 ChunkNotReadyPacket。
  • Worker 遇未生成 chunk → queueUntilGenerated 入 concurrent queue；主緒消費：無效回 sendNotRequired、超範圍入佇列（上限 1024）、有效掛起（上限 4096，超限／生成逾時 30s 回 ChunkNotReady 主動告知 client）。
  • 整個 server 端重試機制刪除：Chunk.retriesCount、MAX_CHUNK_SEND_TRIES、getRetryChunk() 全移除。
  • WorkerThread 從此不再寫 ccrWaiting（回填一律走 concurrent queue）。

C. 記憶體洩漏多因修復＋記憶體優化

  • 新增 PoolCaps（主迴圈每 tick updateServerCaps()）與 CappedConcurrentQueue（有上限池佇列）。
  • IsoChunkMap.chunkStore 與 IsoChunk.loadGridSquare 改型 CappedConcurrentQueue ——這就是舊 loose class 起不來的直接原因。
  • ObjectPool／Pool／ReferencedObjectPool 重構；IsoChunk pool 家族（unlinkSquares、resetForStore 等）；IsoObject highlight/renderInfo 陣列改懶初始化。

D. 快速移動時黑邊/灰塊減少（官方自承「additional causes 仍在調查」）

即 B 的效果面。官方沒修的 additional cause 正是我方 W4-1 定罪的吞吐瓶頸：RequestZipListPacket 逐位元相同（每包仍 new ccr）、update() 每 tick 仍只處理一個 ccr。

其他

  • lighting 錯誤修復（LightingJNI +270）。
  • WorldMapVisited 家族重構＋PlayerVisitedPacket 移除（rejoin 掉圖主題——玩家回報 42.20.3 後仍存在）。
  • 動物管理層（AnimalCell +971 等）、ServerMap.preupdate 精簡、kahlua StringLib 微調。
