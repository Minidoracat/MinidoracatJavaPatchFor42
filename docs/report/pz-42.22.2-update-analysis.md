## 1. 官方 42.22 動了什麼（與本 repo 相關的部分）

全 jar 985 個 class 有變更。本 repo 155 個被修補方法中 48 個本體有變；helper 引用的遊戲成員有 16 個本體有變、5 個被刪；Patcher 命中數漂移 11 處，另有 9 支測試編譯不過。重點：

- **`projectzomboid.jar` 簽章**：每個 entry 有 SHA-256（`PROJECTZ.SF`），簽章者是 TIS 的 EC 金鑰。JVM 對同一個 class loader 同一個 package 的 class 比對簽章者：loose class（沒有簽章者）與 jar 內的 class 混在同一個 package，丟 `SecurityException: class "…"'s signer information does not match signer information of other classes in the same package`，順序反過來也一樣（遊戲自帶 Zulu 25.0.5 實測）。42.21 以前「loose class 放 `java/` 底下、classpath `java/.` 優先」的部署方式因此不能用。
- **新的 `zombie.core.IntegrityReport`**：主選單／開服時在背景檢查 jar（被改、簽章不符、少檔、外來簽章者）、classpath 上 jar 以外的 class、`-javaagent`／`-agentpath`／`-agentlib` 參數，結果附在 `Core.getVersion()`（`jar=tampered,classpath=N,agents=N`），出現在 console、`statistics`、Prometheus `pz_info`。只回報、不擋人；原始碼有一行註解說動它的人可能被 Workshop 永久停權。版本相容檢查用 `getVersionNumber`，不含這段。
- **封包身分**：`PlayerID` 改成 `ConnectionPlayer`／`OnlinePlayer`。伺服器只從送出封包的連線解析玩家（`ConnectionPlayer.parse` 不再查 `GameServer.IDToPlayerMap`），解析不到時 `isConsistent` 為 false、封包在反作弊之前就被丟掉。`Action`／`Transaction` 的 `playerId` 欄位改名 `player`；`ActionManager.stopPlayerActions(PlayerID)` 改成 `(IsoPlayer)`，比對改用 online ID（`isActionOf`）。
- **`NetTimedActionPacket.processServer` 原版開始比對動作的執行者與送出者**（Request 分支 `rawget("character")` 與 `ConnectionPlayer.getPlayer()` 不同就 Reject），本 repo 的 W78 與動作封包 owner 檢查因此退役（§4）。
- **`zombie.util.list.PZArrayList` 刪除**：`IsoGridSquare.getObjects()` 等改回 `List`。
- 其他與各刀相關的改動（W12 車輛 chunk 索引、`IsoObject.syncIsoObjectReceive` 多一個連線參數、`PZNetKahluaTableImpl.load` 加巢狀深度、`ItemDescription`／`SyncClothingPacket` 補 tint 守衛等）寫在 §4 與 `docs/patches.md` 各節的「2026-11-10 42.22.2 對版」。

## 2. 載入機制改成 Java agent

### 2.1 三個選項

| 選項 | 做法 | 結果 |
|---|---|---|
| A | 整個 package 都放 loose（同 package 不混簽章者） | `IntegrityReport` 本身在 `zombie.core`，跟著改從 loose 目錄載入：判 `NOT_A_JAR`、跳過簽章與 classpath 檢查，等於架空官方檢查（本機實測）。不採用 |
| B | Java agent：官方 class 載入時換成手術後的 bytes | 官方 jar 與簽章不動；換上的 class 保留官方 ProtectionDomain 與簽章者；`IntegrityReport` 判 jar 原版、只多 `agents=1`（本機實測）。**採用（使用者裁定 2026-11-10）** |
| C | 用拿掉簽章的 jar 副本開服 | `IntegrityReport` 判 `jar=tampered`；遊戲更新只換原 jar，若 JVM json 指向副本，整份舊程式會跑在新資料上。不採用 |

### 2.2 實作

- `MdcAgent`（`patcher/agent/`）：premain 全包在 try/catch，任何意外都以原版繼續（premain 丟例外會讓 JVM 起不來）。遊戲 jar（`java.class.path` 上的 `projectzomboid.jar`）SHA-256 等於建置基準、payload 每一項 SHA 都對、要換的 class 一個都還沒被載入、classpath 的資料夾裡沒有會蓋掉修補的 loose class（同名檔或 `zombie/mdc/` 底下的 `.class`）才啟用，全有或全無。先註冊 transformer，再以同 package 的原版 class 為錨用 `MethodHandles.Lookup.defineClass` 定義放在原版 package 的 helper：`zombie/network/packets/*` 的類別都實作被修補的 `INetworkPacket`，順序反過來就會先載到原版父型別。定義失敗時以 `retransformClasses` 把已換上的 class 還原成原版（逐個核對 JVM 交回的原始 bytes 的 SHA），照 DISARMED 以原版繼續；還原不完整才結束 JVM（exit 78）。transformer 只換系統 class loader 載入、名稱在表上、原版 bytes SHA 等於建置基準的 class。kill switch `-Dmdc.agent=off`。console 印 `[mdc-agent] ARMED／OFF／DISARMED／NOT APPLIED／FATAL`。（還原、先載入檢查與 loose class 檢查是 2026-11-10 多模型 review 後補的，見 §8。）
- `AgentJarBuilder`：把 `dist/java`（Patcher 輸出＋helper）打成 `dist/mdc-javapatch-agent.jar`（固定時間戳，可重現）與 `agent-manifest.txt`。client 包另有多模組模式（`-javaagent:<jar>=modules=<id>,…`）。
- `AgentLoadCheck`（build.ps1 [5b]）：在官方簽章 jar＋`-javaagent` 的 JVM 裡驗證——armed：每個 class 載得起來並在 `-Xverify:all` 下連結、手術 class 與原版 package helper 帶官方簽章者、換上數＝手術 class 數、`IntegrityReport` jar=ORIGINAL 且 agents=1；`-Dmdc.agent=off`、「jar 不是建置基準」、「別的 agent 先載入要換的 class」、「classpath 有 loose class」四條路一個都不換；故障注入讓 helper 定義失敗時，已換上的 class 全部還原。
- 測試 jar：行為測試、LoadCheck、BytecodeVerify、SmokeCheck 都是把 `dist/java` 放 classpath 前面覆蓋原版，對簽章 jar 一樣會 `SecurityException`，所以 build.ps1 用 `UnsignedTestJar` 產生拿掉簽章檔的測試 jar（class bytes 相同）。
- 部署：`install.sh` 裝到 `serverfiles/mdc-javapatch/`（agent jar SHA、jar 同源、衝突三道閘）；`uninstall.sh` 把整個目錄搬到 `patch-disabled-*`。`run-with-pfguard.sh` 新增 agent 啟動閘：兩個 SHA 都對才把 `-javaagent` 加進 `JAVA_TOOL_OPTIONS`，不符印 `[mdc-javagate] AGENT DISARMED` 以原版開服。注入點不放 JVM json：agent jar 不見時 json 寫死的 `-javaagent` 會讓 JVM 起不來，json 也會被 Steam／LinuxGSM 重置。`-javaagent` 不改 `java.class.path`，`IntegrityReport` 的 classpath 計數不受影響（實測）。

### 2.3 連帶改變的維運規則

- 遊戲更新換了 jar，agent 自己不啟用，伺服器以原版開服，不再有「新 jar＋舊 loose class」混跑；「更新前必須搶先 uninstall」改成建議。
- `uninstall.sh` 搬走的是 JVM 開服時就開著的 jar，執行中的 JVM 不受影響，沒有 loose class 時代「刪檔後冷路徑 `NoClassDefFoundError`、worker 死掉全服假死」的風險，不必立刻重啟。

## 6. 部署

部署要服主授權。步驟：上傳 staging（payload SHA 核對）→ `install.sh` 裝到 `serverfiles/mdc-javapatch/` → wrapper 換成新版前先對 staging 那份 dry run（要印 `AGENT ARMED` 與 pfguard PASS），換上後再 dry run 一次，失敗就換回並 uninstall。下次重啟生效，驗收照 `docs/patches.md` §3（`[mdc-javagate] AGENT ARMED`、`[mdc-agent] ARMED`、`Core.getVersion()` 的 `agents=1`、沒有 `SecurityException`）。JVM json 不用改。

## 8. 多模型 review 後的修正（2026-11-10）

整個 branch 交三個不同模型各自完整 review（唯讀），下列各項經逐條覆核成立後修正；修正後再交兩個模型複核。

|---|---|---|

複核（兩個模型）再指出三項，也已修正：還原與別的執行緒同時載入 class 之間的競態（切到還原模式與 transformer 的判定改用同一把鎖，新增多執行緒測試；拿掉鎖時測試會失敗）；沒有安裝紀錄的卸載在啟動設定讀不出來時回報「沒有東西需要卸載」（改成中止）；「本包排最前面就先拿到原版 class」的說法不成立，文案與註解改成分情況寫（JVM 先跑所有 retransformation incapable 的 transformer；capable 的 Java transformer 照啟動參數的順序；排在本包之後的與 capable 的 native agent 改的是修補版，本包看不到：同改一個 class 的組合不支援，見 [docs/patches.md](../patches.md) 開頭「和別的 Java agent 並存」）。另外補上：別的 agent 或除錯器把已換上的 class `redefineClasses` 成別的 bytes 時不蓋回去、記 `NOT APPLIED`；`AgentJarBuilder` 的形狀檢查加上欄位順序與 NestHost／NestMembers／Record／PermittedSubclasses；`AgentLoadCheck` 加一個情境，由第二個 agent 對全部已換上的 class 做一次真的 retransform，確認每一個都再拿到同一份修補。遊戲自帶的 JRE（Zulu 25.0.5）實跑過啟用、還原與 retransform 三條路。
