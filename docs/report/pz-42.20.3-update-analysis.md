## 1. 官方 42.20.3 動了什麼（changelog × bytecode 實證）

全 jar 23,735 → 23,740 class：**新增 6、移除 1、變更 143**。四大主題：

### A. MP 玩家上限 254＋滿員時管理員可進（changelog「player limit handling」）

- `GameServer`：新增 delayed-disconnect 機制（`MainLoopDelayedDisconnectQ`、
  `addDelayedDisconnect`/`doDelayedDisconnect`/`isDelayedDisconnect`）、`getFreeSlot` 收為
  private、`receiveClientConnect` 重構；`UdpConnection`/`UdpEngine`/`QueuePacket` 配合。
- `LoginPacket.processServer`：client 版本不符時**提前 `return`**（舊版 log+踢人後繼續跑完
  登入流程＝bug）。

### B. client 卡「Loading Map」forever 修復（chunk 供給管線重構）——**與我方 W4-1 同戰場**

- `PlayerDownloadServer`（+6,335 bytes，9→16 方法）新增 pending 機制：
  - 新內部類 `QueuedRequest`／`PendingChunk`／`OutOfRangeRequest`＋新封包
    `ChunkNotReadyPacket`。
  - Worker 遇未生成 chunk → `queueUntilGenerated` 入 `queuedByWorker`
    （ConcurrentLinkedQueue）；主緒 `updatePendingChunks()` 消費：無效 chunk 回
    `sendNotRequired`、超範圍入 `outOfRangeRequests`（上限 1024）、有效入 `pendingChunks`
    （LinkedHashMap，上限 4096，超限／生成逾時 30s 直接回 `ChunkNotReady` 告知 client）。
    生成完成後組新 ccr 塞回 `ccrWaiting`。
  - **整個 server 端重試機制刪除**：`Chunk.retriesCount`、`MAX_CHUNK_SEND_TRIES`、
    `getRetryChunk()` 全移除（42.20.2 的「3 次重試放棄」不復存在）。
  - `isRequestCancelled`/`sendNotRequired` 介面從 Chunk 實例改 requestNumber（int）。
  - **WorkerThread 從此不再寫 `ccrWaiting`**（回填一律走 concurrent queue）。
- client 端 `WorldStreamer`（+355）配合收 `ChunkNotReady`；`GameClient`（+110）。

### C. 記憶體洩漏多因修復＋記憶體優化（changelog「memory leak」「memory optimisations」）

- 新增 `zombie/popman/PoolCaps`（`GameServer.main` 每 tick `updateServerCaps()`）與
  `zombie/util/CappedConcurrentQueue`（有上限的池佇列）。
- `IsoChunkMap.chunkStore` 與 `IsoChunk.loadGridSquare` 改型 `CappedConcurrentQueue`
  ——**這就是舊 loose class 起不來的直接原因**。
- `ObjectPool`（+633）/`Pool`/`ReferencedObjectPool` 重構；`IsoChunk` pool 家族
  （`discardSquares`→`unlinkSquares`、`resetForStore`、`doReuseGridsquares`、
  `getFromPool`、`LoadBrandNew`）；`WorldReuserThread`。
- `IsoObject`：`highlightColor[]`／`renderInfo[]` 由建構子預配改**懶初始化**
  （新 `getOrCreateHighlightColor`）——每物件省兩個陣列＋元素物件。
- `GenericSpriteRenderState`（−1,435）、`ModelManager`、`LightingJNI`（lighting 錯誤修復）。

### D. 快速移動時黑邊/灰塊減少（changelog 明言「additional causes 仍在調查」）

即 B 的效果面。**官方沒修的 additional cause 正是我方 W4-1 定罪的吞吐瓶頸**（見下節）。

### 其他

- `WorldMapVisited`/`WorldMapVisitedServer`/`WorldMapClient` 重構、`PlayerVisitedPacket`
  移除、`RequestDataPacket`（+898）——rejoin 世界地圖同步主題（玩家回報「rejoin 掉圖」
  42.20.3 後仍存在）。
- 動物：`AnimalCell`（+971）/`AnimalChunk`/`AnimalManagerWorker`/`AnimalZones`。
- `ServerMap.preupdate` 刪 cancelLoading 處理段（−567）；kahlua `StringLib` 微調。

### 42.20.3 上線後觀察到的新 vanilla bug（正式服實測，2026-08-18）

- **`SyncItemFieldsPacket.parse(:383)` NPE ×201/11h**：client 同步 server 上不存在的
  item，`item.hasSharpness()` 無 null 防護——例外打到 `GameServer.main(:909)` 主迴圈層，
  每包浪費一圈（非活鎖、不踢人）。可另行回報 TIS。
- **`GameEntityManager.checkEntityIDChange(:400)` 格式字串含 `%l`** →
  `UnknownFormatConversionException`（Java Formatter 不支援 C 風格 `%l`）——觸發場景：
  批次斷線後 chunk 卸載鏈（`ServerCell.Unload`→`IsoChunk.removeFromWorld`→Unregister）
  想印 entity ID change 錯誤時炸掉，**原始診斷資訊全數丟失**且例外上拋吃掉該 frame 的
  postupdate。×10/11h。可另行回報 TIS。
- **04:02:47 全服批次斷線**（同秒 23 名玩家 RakNet connection-lost，admin 首個）：
  斷線前 12.7 秒窗主迴圈 9.8fps 正常＝**非 server 凍結**；整天僅此一次＝一次性網路層
  事件（出口/虛擬化層），與 patch 無關（全計數器健康）。上述 `%l` 例外即其下游。

### 需要行為觀測的一項：W4-1

TIS 的 pending 機制解決的是「**未生成** chunk 請求佔住管線＋client 盲等」；我方 W4-1 解決的
是「**已生成** chunk 的供給吞吐只有設計值 15%」。兩者正交、掛點相容（已逐指令驗證），但生效
後應觀測：

- `ChunkPacker` 週期 log 的 `mergedChunks`／`avgBatchX10`——若官方 pending 回填讓佇列形狀改變
  （例如回填 ccr 已接近滿），`packed` 比例會自然下降，屬預期而非故障。
- `anomalies` 必須恆 0；`overrunTicks` 比率維持 0.1x% 量級。
- 官方 `ChunkNotReady` 上線後 client 不再對未生成 chunk 盲等重發——42.20.2 觀測到的
  「pending≈240、周期性重發」形狀會消失，屬官方修復效果，勿誤判為 W4-1 失效。

### 唯一退場項

- **SmokeCheck 的 `retriesCount` 斷言**（W9 私有池「新殼 retriesCount=0」）——vanilla 欄位
  連同重試機制整個刪除，斷言目標消失，已改為只驗 `bb`（fresh-shell 等價命題的剩餘部分）。
  helper 本體零改動。
